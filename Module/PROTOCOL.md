# IMU 模块通信协议 v1

本轮更新协议与资源预算，通信实现安排在产品业务接入阶段。

## 公共约定

- IMU 的 gyro、acc 各采样 7680 Hz，CAN 和 UART 各发布 1000 组 IMU 数据每秒。
- 每组包含四元数 4 项、加速度 3 项和角速度 3 项，全部测量字段使用有符号 int16。
- 多字节字段采用小端序，按字节偏移编码。
- 两路输出来自同一结果快照，CAN 加速度帧、角速度帧及 UART 负载使用相同的 16 bit 发布序号。
- 序号位模式按 uint16 模 65536 递增，1 kHz 时约 65.536 s 回绕。
- 四元数顺序为 `[w,x,y,z]`，表示传感器安装坐标系到 Z-up 参考系的旋转。
- 加速度和角速度从两路最新解包物理量反向恢复为器件 X/Y/Z 轴的 int16 输出码。
- 7680 Hz 样本全部送入融合，1 kHz 发布时取得最新驱动物理量与四元数快照，执行反向封包。
- 航向参考由初始化确定。上位机使用 `Rz(yaw) Ry(pitch) Rx(roll)` 换算角度制欧拉角。

器件采样时间戳用于模块内部排序、积分和融合。接收端通过序号对应 UART 与 CAN 的加速度、角速度，并记录四元数帧的接收时刻。
本版测量消息由序号与十个 int16 测量字段组成。

## 四元数编码与原始样本封包

四元数按 32767 倍编码。加速度与角速度通过逆向计算恢复 LSM6DSV16X 输出码，采用器件坐标系与小端字节序。

| 测量字段 | 发送内容 | 接收端解释 | 当前量程 |
|---|---|---|---|
| qw/qx/qy/qz | round(q × 32767) | 编码值 / 32767，再归一化 | 单位四元数 |
| ax_raw/ay_raw/az_raw | 从驱动加速度反向恢复的 int16 码值 | 按对应量程灵敏度转换 | ±4 g |
| gx_raw/gy_raw/gz_raw | 从驱动角速度反向恢复的 int16 码值 | 按对应量程灵敏度转换 | ±2000 °/s |

四元数的 `round` 采用就近取整，中点远离零，编码范围为 `[-32767,32767]`。
加速度和角速度反向取整后限幅至 `[-32768,32767]`，再转换成 int16 并封包。
四元数无有效结果时，四个四元数字段置零，接收端用零范数识别姿态无效。已获取的驱动物理量按最新值反向封包。
发布测量组前完成两路首帧采集，建立有效的物理量快照。

### 驱动与通信的数据路径

以 `acc_sample_t::Accel`、`gyro_sample_t::Gyro` 的最新解包物理量为发送数据源。
发布快照同时取得这些物理量、四元数，以及该样本解包时使用的量程、灵敏度、驱动静态偏置和安装方向参数。
发送期间快照保持稳定。参数切换与样本交接由采集任务协调，确保反向运算采用该样本的解包参数。

驱动正向处理为单位换算、静态偏置校正、安装方向映射。
通信反向处理先逆安装方向，再对角速度加回驱动静态偏置，最后除以相应转换系数并就近取整。
令 M 为器件系到安装坐标系的变换，b 为器件系下的驱动静态角速度偏置，则有

```text
Sa = acc_range_g * 9.80665 / 32768
Sg = gyro_dps_per_lsb * pi / 180

acc_installed  = M * (acc_raw * Sa)
gyro_installed = M * (gyro_raw * Sg - b)

acc_raw  = round((transpose(M) * acc_installed) / Sa)
gyro_raw = round((transpose(M) * gyro_installed + b) / Sg)
```

`Sa`、`Sg` 的计算使用与驱动正向解包相同的常量和乘除关系。
当前角速度字段来源于驱动样本，逆变换中的 b 为驱动解包时扣除的静态偏置。
逐轴完成逆变换后先检查有限性，再就近取整、中点远离零，限幅后转为 int16。
封包顺序为 X 低字节、X 高字节、Y 低字节、Y 高字节、Z 低字节、Z 高字节。

实现验证覆盖原码全范围、各量程、安装方向映射与静态偏置，验收目标为恢复的 int16 码值与解包前原码一致。
通信数据来源统一为最新解包物理量及其解包参数。
规划阶段的主机 float32 往返校核已覆盖全部 int16 码值、四种加速度量程、六种角速度量程、八种安装方向和三组角速度偏置。
共校核 34603008 次逐轴转换，取整前最大误差为 0.005859375 LSB，恢复码值全部相同。产品接入阶段继续核对实际驱动与线上字节。

### 接收方物理量转换

接收方按器件量程与手册灵敏度换算。当前 ±4 g、±2000 °/s 配置下，手册表 3 的典型灵敏度为

```text
acc_g      = acc_raw * 0.000122
acc_mps2   = acc_g * 9.80665
gyro_dps   = gyro_raw * 0.070
gyro_rps   = gyro_dps * pi / 180
```

量程变化时，接收方同步更新灵敏度。原始值的坐标系为器件 X/Y/Z，四元数沿用产品配置的安装坐标系。
若接收方需要将原始向量与四元数配合使用，按相同安装方向映射处理向量。

## 公共测量负载

负载 P 固定为 22 B，由一个序号字和十个测量字组成。

| 偏移 | 长度 | 字段 | 编码类型 |
|---|---|---|---|
| 0 | 2 | sequence | 16 bit 序号 |
| 2 | 2 | qw | int16 |
| 4 | 2 | qx | int16 |
| 6 | 2 | qy | int16 |
| 8 | 2 | qz | int16 |
| 10 | 2 | ax_raw | 器件原始 int16 |
| 12 | 2 | ay_raw | 器件原始 int16 |
| 14 | 2 | az_raw | 器件原始 int16 |
| 16 | 2 | gx_raw | 器件原始 int16 |
| 18 | 2 | gy_raw | 器件原始 int16 |
| 20 | 2 | gz_raw | 器件原始 int16 |

## UART 帧

链路为 USART2，921600 波特率，8N1。完整帧共 30 B。

| 帧内偏移 | 长度 | 字段 | 数值或说明 |
|---|---|---|---|
| 0 | 2 | 帧头 | 字节 `A5 5A` |
| 2 | 1 | version | 0x01 |
| 3 | 1 | message_type | 0x01，IMU 测量 |
| 4 | 2 | payload_length | uint16，0x0016，即 22 B |
| 6 | 22 | payload | 公共测量负载 P |
| 28 | 2 | crc16 | 对帧内字节 2..27 计算 CRC16 |

UART 使用 CRC-16/CCITT-FALSE。

| 参数 | 数值 |
|---|---|
| width | 16 |
| poly | 0x1021 |
| init | 0xFFFF |
| refin / refout | false / false |
| xorout | 0x0000 |
| 校验向量 | ASCII `123456789` → 0x29B1 |
| 线上字节顺序 | CRC 低字节在前 |

v1 最大负载长度为 64 B，IMU 测量类型固定为 22 B。
接收按字节流处理，支持一帧跨越 DMA 接收块，以及多个完整帧同处一个接收块。
接收端查找帧头后验证版本与长度，收齐帧后验证 CRC，再交付负载。
长度或 CRC 错误时，从候选帧头后一字节继续搜索。完整未知消息类型按长度与 CRC 校验后跳过。

1 kHz 输出为 30000 B/s，8N1 在线上传输约 300000 bit/s，占 921600 波特率约 32.6%。

## 经典 CAN 三帧

使用 11 位标准数据帧，速率 1 Mbit/s，每帧 DLC=8。
校验由 CAN 控制器执行帧级 CRC。四元数帧独立交付，加速度与角速度按相同序号配对。
节点号 `node_id` 为编译期配置，取值 0..31，默认值为 1。

```text
base_id = 0x300 + node_id * 0x10
frame_id = base_id + frame_index
frame_index = 0..2
```

默认节点的 ID 为 `0x310、0x311、0x312`。每帧包含四个 16 bit 字，字节序均为小端。

| CAN ID | 字节 0..1 | 字节 2..3 | 字节 4..5 | 字节 6..7 |
|---|---|---|---|---|
| base_id + 0 | qw | qx | qy | qz |
| base_id + 1 | sequence | ax_raw | ay_raw | az_raw |
| base_id + 2 | sequence | gx_raw | gy_raw | gz_raw |

第一帧完整携带四个四元数分量，第二帧与第三帧携带相同发布序号。
三帧共 24 B，包含 20 B 测量值与两个 16 bit 序号。

### 发送与重组

发送端按 `base_id+0 → base_id+1 → base_id+2` 顺序提交一组，并保持同一节点各组的发送顺序。
同一组数据全部来自同一次快照。发送过程中快照保持稳定。
接收端按节点号和消息 ID 处理。

1. 收到 `base_id+0`，取得 qw/qx/qy/qz，独立更新四元数及本机接收时刻。
2. 收到 `base_id+1`，按 sequence 保存 ax_raw/ay_raw/az_raw，并记录接收时刻。
3. 收到 `base_id+2`，按 sequence 保存 gx_raw/gy_raw/gz_raw。
4. 同序号的加速度与角速度收齐后交付这一对数据。从收到其中一帧起计时，5 ms 超时后丢弃尚未配齐的数据。

同序号、同类型、相同内容的重复帧保留一次，内容冲突时使该序号的数据对失效。
接收时按 CAN 帧到达顺序处理，其他节点与其他 ID 由各自处理逻辑接收。
联合使用四元数与原始向量时，按发送顺序和接收时刻选择邻近结果。
连续丢帧、积压或跨周期到达时，四元数与原始向量的严格组对应存在歧义。

1 kHz 对应每秒 3000 个 CAN 帧。按每帧含位填充和帧间隔 135 bit 保守预算，约占 40.5% 总线带宽。
实际预算还需纳入其他节点、错误重传和仲裁延迟。

G431 当前 HAL 的 Tx FIFO 为三个元素，一组即可占满三个槽。
产品发送端使用有界队列逐步提交，忙时保留尚未发送的内容并重试，按整组推进发送。
发送队列拥塞时优先保留最新未开始发送的完整快照，接收端通过序号跳变观察丢组。
现有驱动的 FIFO 满时撤销待发帧行为，需要在业务接入前修正。

## 字节测试向量

取 sequence=`0x1234`，四元数 `[1,0,0,0]`，加速度原始码 `[0,0,8192]`，角速度原始码 `[1000,-2000,3000]`。
对应十个 int16 测量值为 `[32767,0,0,0,0,0,8192,1000,-2000,3000]`。

UART 完整帧为 30 B，CRC16 数值为 `0x4C92`。

```text
00 00 00 00 00 20 E8 03 30 F8 B8 0B 92 4C
```

```text
ID 0x310    FF 7F 00 00 00 00 00 00
```
